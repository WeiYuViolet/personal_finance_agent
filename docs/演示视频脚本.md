# 演示视频脚本（3-5 分钟）

> 用于录制期末大作业第 3 项提交物：演示视频。
> 建议时长约 4 分 30 秒；工具：OBS / 系统录屏 + 麦克风，提前把终端、Gradio 界面、`docs/设计文档.md` 的架构图准备好。

---

## 0. 录制前准备

1. 已 `cp .env.example .env` 并填入 DeepSeek（或任意 OpenAI 兼容）密钥；
2. 已 `pip install -r requirements.txt`，中文字体已装（Linux `fonts-noto-cjk`）；
3. 终端执行 `python run.py`，浏览器打开 `http://127.0.0.1:7860`；
4. 右侧已自动写入 `default` 用户近三个月演示账单（`SEED_DEMO_DATA=1`）；
5. 架构图已导出为 PNG：`docs/architecture.png` 与 `docs/sequence.png`，录制时直接打开这两张图，供背景介绍与技术讲解环节切屏。

## 2. 分镜与讲稿

### 镜头 0 · 片头（0:00–0:15）
**画面**：深色标题页，居中「本地个人财务记账智能体」，副标题「ReAct 智能体 · 工具调用 · 长期账本 · RAG 理财笔记 · 消费可视化」。

**讲稿**：
> 大家好，这是人工智能综合实践大作业——「本地个人财务记账智能体」。它能让你用一句话完成记账、查账、出图和理财建议，数据全部保存在本地。

---

### 镜头 1 · 选题背景与目标（0:15–0:45）
**画面**：切换到设计文档的**整体架构图**。

**讲稿**：
> 大学生每个月生活费有限，普遍存在"记账坚持不下来、月底不知道钱花在哪"的问题。市面上的记账软件多是固定表单，缺少自然语言交互和自动分析。所以我做了一个本地、可离线运行的智能体：你用口语说一句，它自己完成"记账 → 查账 → 生成图表 → 检索本地理财笔记 → 输出省钱建议"的多步任务。
> 技术栈是 Python + LangChain + LangGraph 的 ReAct 循环，配合 SQLite 长期记忆和离线 TF-IDF 检索，前端用 Gradio。

---

### 镜头 2 · 启动与界面（0:45–1:10）
**画面**：终端 `python run.py` 输出「RAG 知识库索引完成、已写入演示账单」，浏览器切到 Gradio 界面。

**讲稿**：
> 一条命令启动。左边是对话区，右边是账本面板：月预算、最近三天账单、统计图、笔记上传和删除确认。首次启动会自动建库，并为演示用户写入近三个月账单。右上角填不同用户 ID，就能体验多用户账本隔离。

---

### 镜头 3 · 核心功能演示（1:10–3:05）

#### 3.1 自然语言记账（1:10–1:35）
**操作**：在输入框输入：
> 记一笔，今天中午食堂吃饭花了 18 块，餐饮

**画面**：智能体调用 `add_bill_record`，右侧"最近三天账单"表格实时多出一行。

**讲稿**：
> 先看记账。我只说了一句"今天中午食堂花了 18 块，餐饮"，智能体自动抽取金额、分类和日期，调用记账工具写入 SQLite，右侧账单表格立刻刷新。这里体现了 Function Calling：工具描述就是参数说明，模型据此抽参。

#### 3.2 多步分析与可视化（1:35–2:35，核心镜头）
**操作**：输入：
> 帮我统计本月开销，看看餐饮占比，同时给我下个月省钱建议

**画面**：依次展示三个工具的串行调用与返回，最终出现**饼图**和分析报告。

**讲稿**：
> 这是核心镜头。这一句话触发了三步串行调用：第一步 `query_monthly_bills` 读账本，得到本月收支结余和分类占比；第二步 `generate_spending_chart` 用 matplotlib 生成分类饼图；第三步 `search_finance_notes` 做 RAG 检索，从本地理财笔记里找到"控制餐饮开销"的依据。最后智能体综合输出分析报告，并注明建议来自哪篇笔记。这就是 ReAct 循环：模型先想清楚（Thought）、再调工具（Tool Call）、拿到结果（Observation）再继续，直到完成。

#### 3.3 记忆与多用户隔离（2:35–2:55）
**操作**：把右上角"用户ID"改成 `alice`，输入：
> 我月预算 2000，帮我看看这个月花了多少

**画面**：预算面板显示 2000 元，统计的是 alice 自己的（空）账本，与 default 互不影响。

**讲稿**：
> 智能体还有长期记忆：月预算、历史账单都存在 SQLite，每轮对话都会召回注入提示词。切换到另一个用户 ID，账本、预算、自定义分类完全隔离，不会串账。

#### 3.4 删除账单闭环（2:55–3:05）
**操作**：说"把今天中午那笔删掉" → 智能体先 `query_monthly_bills` 定位、再 `delete_bill_record` **锁定**；右侧出现【确认删除】按钮，点击后真正删除。

**讲稿**：
> 删除是不可逆操作，所以做了二次确认：智能体只"锁定"待删账单并回传详情，必须由用户在界面点【确认删除】才真正落库，并且带用户校验防越权。

---

### 镜头 4 · 技术架构讲解（3:05–4:05）
**画面**：回到架构图，可快速切到 `agent.py` / `tools.py` 关键代码。

**讲稿**：
> 最后讲一下架构。整体分四层：交互层是 Gradio；编排层用 LangGraph 的 `create_react_agent` 跑 ReAct 循环；工具层注册了九个 LangChain 自定义工具；数据层是 SQLite 账本、TF-IDF 知识库和图表目录。
> 三个关键设计：第一，用户身份通过 contextvars 在调用前注入，模型不用猜 user_id，天然防越权；第二，RAG 用字符 n-gram 的 TF-IDF，中文无需分词、零外部依赖、开箱可复现，接口独立可平滑换成向量库；第三，短期记忆用限长队列防止上下文膨胀，长期记忆落 SQLite，实现跨会话个性化。

---

### 镜头 5 · 结尾（4:05–4:30）
**画面**：收尾页，列出亮点与优化方向。

**讲稿**：
> 总结一下：这个智能体不是工具的堆砌，而是一个有机系统——ReAct 编排、九个工具、短期与长期两级记忆、离线 RAG 检索，共同构成"记录—统计—可视化—建议"的完整闭环。
> 后续可以换成向量检索提升语义召回、把短期记忆持久化、增加预算超支主动提醒。谢谢大家。
